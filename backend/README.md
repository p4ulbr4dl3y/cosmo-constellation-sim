# Cosmo Satellite Constellation Simulation Service

Бэкенд-сервис для моделирования спутниковых группировок, маршрутизации и оценки устойчивости связи в Арктике (КосмоХакатон 2026, кейс №2).

## Стек технологий
- Python 3.12+
- Менеджер пакетов: `uv`
- Веб-фреймворк: `FastAPI`, `uvicorn`
- Математика и геометрия: `NumPy`
- Схемы и валидация: `Pydantic`
- Тестирование и линтинг: `pytest`, `pytest-cov`, `ruff`

## Быстрый старт

### Установка зависимостей
```bash
cd backend
uv sync
```

### Запуск сервиса
```bash
cd backend
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```
Интерактивная документация Swagger/OpenAPI доступна по адресу:
`http://localhost:8000/docs`

### Запуск тестов и линтера
```bash
cd backend
uv run pytest -v
uv run ruff check
```

## Консольная утилита (CLI)

Сервис включает полнофункциональную CLI-утилиту для автоматизированного расчета сценариев без браузера:

```bash
# Расчет всех эталонных сценариев из 'data/'
cd backend && uv run python -m app.cli --all

# Расчет конкретного сценария с выводом метрик SLA
cd backend && uv run python -m app.cli --scenario ../data/01_full_constellation.json

# Расчет сценария с сохранением результата в cosmo-A-result-1.0
cd backend && uv run python -m app.cli --scenario ../data/01_full_constellation.json --export ../result.json
```

## Эндпоинты REST API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/health` | Проверка работоспособности сервиса |
| `GET` | `/api/presets` | Список доступных эталонных сценариев из каталога `data/` |
| `GET` | `/api/presets/{name}` | Загрузка JSON-сценария по имени |
| `POST` | `/api/validate` | Валидация структуры `cosmo-A-1.0` с выводом ошибок на русском |
| `POST` | `/api/simulate` | Полный расчет горизонта (720 шагов), метрики доступности, таймлайны и причины отказов |
| `POST` | `/api/snapshot` | Расчет одного временного кадра `t_s` для 2D/3D визуализации |
| `POST` | `/api/export` | Экспорт результатов в официальном формате `cosmo-A-result-1.0` |
| `POST` | `/api/compare` | Сравнение двух сценариев (A и B): дельта параметров, доступности и SLA |
| `POST` | `/api/recommendations` | Инженерные рекомендации по устранению узких мест группировки |
| `POST` | `/api/report/export` | Генерация и выгрузка аналитического Markdown-отчета |

## Классификация отказов
При отсутствии сквозного маршрута от клиента к шлюзу сервис определяет первопричину:
1. `no_client_satellite` — нет активного спутника над клиентом (клиент вне зоны радиовидимости).
2. `gateway_offline` — все наземные шлюзы находятся на техническом обслуживании или отключены.
3. `no_gateway_satellite` — шлюзы активны, но в их зоне видимости нет ни одного спутника.
4. `isl_disconnected` — спутники видны над клиентом и над шлюзом, но межспутниковая сеть (ISL) разорвана.
