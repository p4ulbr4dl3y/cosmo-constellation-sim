# Описание данных: Проектирование устойчивой спутниковой группировки

## Состав данных и начало работы

Один файл JSON содержит один проект группировки и условия его расчёта. Для начала работы используйте `01_full_constellation.json`. Сервис загружает файл, отображает параметры и рассчитывает состояние сети на заданном периоде. Изменение настроек в интерфейсе создаёт новый вариант проекта.

### Эталонные файлы данных ([data/](../data/))

| Файл | Содержание |
|---|---|
| [`01_full_constellation.json`](../data/01_full_constellation.json) | 48 аппаратов, 3 плоскости, 3 наземных пункта и 1 шлюз. Расчёт на сутки. |
| [`02_first_launch.json`](../data/02_first_launch.json) | Тот же проект на первой очереди запуска: активны 16 аппаратов (1 плоскость). |
| [`03_satellite_outages.json`](../data/03_satellite_outages.json) | Десять аппаратов недоступны с шестого часа ($t \ge 21\,600$ с) до конца расчёта. |
| [`04_link_range.json`](../data/04_link_range.json) | Полная группировка при ограниченной дальности межспутниковой связи (2000 км). |

Формат файлов - JSON, кодировка UTF-8. Время отсчитывается от начала расчёта в секундах. Идентификаторы связывают объекты внутри файла. Сценарий может содержать другие названия и идентификаторы при сохранении структуры данных.

## Структура сценария (`cosmo-A-1.0`)

| Раздел | Содержание |
|---|---|
| `schema_version` | Версия структуры данных: строго `"cosmo-A-1.0"`. |
| `meta` | Поля `id` и `title`: идентификатор и название сценария. |
| `environment` | Орбита, параметры связи и сетка времени. |
| `design` | Плоскости, спутники и выбранная очередь запуска (`launch_stage`). |
| `ground_sites` | Наземные клиентские пункты (`client`) и шлюзы (`gateway`). |
| `failures` | Периоды недоступности спутников (пустой список - нет отказов). |
| `gateway_outages` | Периоды технического обслуживания и недоступности наземных шлюзов. |

## Параметры расчёта (`environment`)

| Поле | Тип | Назначение и базовое значение |
|---|:---:|---|
| `altitude_km` | `float` | Высота круговой орбиты в километрах; в наборе `550`. |
| `inclination_deg` | `float` | Наклонение орбиты в градусах; в наборе `87`. |
| `earth_angle0_deg` | `float` | Начальный угол поворота Земли относительно координатных осей, градусы. |
| `horizon_s` | `int` | Продолжительность горизонта расчёта в секундах; в наборе `86400` (24 ч). |
| `step_s` | `int` | Шаг дискретизации расчёта в секундах; в наборе `120` (720 точек). |
| `min_elevation_deg` | `float` | Минимальный угол возвышения над горизонтом для связи с Землей; в наборе `10`. |
| `isl_range_km` | `float` | Предельная дальность межспутниковой линии (ISL) в км: `3000` (или `2000`). |
| `target_availability` | `float` | Целевой уровень доступности в долях единицы; `0.9` соответствует 90%. |

> **Сетка времени**: расчёт выполняется в моменты $t = 0, 120, 240, \dots, 86\,280$ секунд (интервалы $[t, t + \Delta t)$). Правый конец периода ($86\,400$ с) в список отсчётов не включается.

## Конфигурация группировки (`design`)

Параметр `launch_stage` - номер выбранной очереди запуска (1, 2 или 3). В расчёте участвуют спутники, у которых `launch_batch <= launch_stage`, с учётом периодов их недоступности.

| Объект и поле | Тип | Назначение |
|---|:---:|---|
| `planes[].id` | `str` | Уникальный идентификатор орбитальной плоскости (например, `"P1"`). |
| `planes[].raan_deg` | `float` | Прямое восхождение восходящего узла (RAAN), градусы $[0, 360)$. |
| `planes[].phase_deg` | `float` | Начальный угловой сдвиг спутников вдоль орбиты плоскости, градусы $[0, 360)$. |
| `satellites[].id` | `str` | Уникальный идентификатор спутника (например, `"S101"`). |
| `satellites[].plane_id` | `str` | Идентификатор плоскости из `planes`. |
| `satellites[].slot_deg` | `float` | Базовое угловое положение спутника в плоскости; к нему прибавляется `phase_deg`. |
| `satellites[].launch_batch` | `int` | Очередь вывода спутника: 1, 2 или 3. |

## Наземные пункты и отказы

### `ground_sites`:
Каждый элемент содержит `id`, `name`, `role`, `lat_deg`, `lon_deg`:
- `role`: `"client"` (клиентский пункт связи) или `"gateway"` (наземный шлюз);
- `lat_deg`: широта $[-90^\circ, +90^\circ]$;
- `lon_deg`: долгота $[-180^\circ, +180^\circ]$.

### `failures` и `gateway_outages`:
- `failures`: массив `{ "satellite_id": str, "start_s": int, "end_s": int }`;
- `gateway_outages`: массив `{ "gateway_id": str, "start_s": int, "end_s": int }`;
- интервал полуоткрытый: $[t_{\text{start}}, t_{\text{end}})$. Например, $[21\,600, 43\,200)$ действует с 6-го по 12-й час.

## Математическая модель и формулы расчёта

### Константы:
- радиус Земли: $R = 6371$ км;
- гравитационный параметр: $\mu = 398\,600.435507 \text{ км}^3/\text{с}^2$;
- звёздные сутки: $T_E = 86\,164.09054$ с;
- радиус круговой орбиты: $r = R + h$;
- орбитальная угловая скорость: $n = \sqrt{\mu / r^3}$.

### Координаты спутника в ECEF
Для плоскости с $\Omega = \text{raan\_deg}$, $i = \text{inclination\_deg}$ и аргумента широты $u(t) = \text{slot\_deg} + \text{phase\_deg} + n \cdot t$:

**В инерциальной системе (ECI):**
$$x = r \cdot (\cos\Omega \cos u - \sin\Omega \sin u \cos i)$$
$$y = r \cdot (\sin\Omega \cos u + \cos\Omega \sin u \cos i)$$
$$z = r \cdot \sin u \sin i$$

**Переход во вращающуюся гринвичскую систему (ECEF):**
$$\theta(t) = \text{earth\_angle0\_deg} \cdot \frac{\pi}{180} + \frac{2\pi t}{T_E}$$
$$x_e = \cos\theta \cdot x + \sin\theta \cdot y$$
$$y_e = -\sin\theta \cdot x + \cos\theta \cdot y$$
$$z_e = z$$

### Координаты наземного пункта
Для широты $\varphi$ и долготы $\lambda$:
$$\mathbf{g} = R \cdot (\cos\varphi \cos\lambda, \; \cos\varphi \sin\lambda, \; \sin\varphi)$$

### Угол возвышения
Для спутника $\mathbf{s}$ и наземной станции $\mathbf{g}$:
$$\theta_{\text{elev}} = \arcsin\left(\frac{(\mathbf{s} - \mathbf{g}) \cdot \mathbf{g}}{\|\mathbf{s} - \mathbf{g}\| \cdot R}\right) \cdot \frac{180^\circ}{\pi}$$
Линия доступна при $\theta_{\text{elev}} \ge \text{min\_elevation\_deg}$ и активном КА / шлюзе.

### Межспутниковые линии связи (ISL):
Для двух активных аппаратов с координатами $\mathbf{a}$ и $\mathbf{b}$:
- расстояние: $\|\mathbf{b} - \mathbf{a}\| \le \text{isl\_range\_km}$;
- просвет над Землей: отрезок $[\mathbf{a}, \mathbf{b}]$ не должен пересекать шар радиуса $R$:
  $$\mathbf{d} = \mathbf{b} - \mathbf{a}, \quad q = \text{clip}\left(-\frac{\mathbf{a} \cdot \mathbf{d}}{\mathbf{d} \cdot \mathbf{d}}, 0, 1\right)$$
  $$\text{min\_dist} = \|\mathbf{a} + q \mathbf{d}\| \ge R.$$

## Формат экспорта результатов (`cosmo-A-result-1.0`):

Выгружаемый JSON содержит:
- `schema_version`: `"cosmo-A-result-1.0"`;
- `effective_scenario`: полный запущенный сценарий (включая все пользовательские правки);
- `routes`: список маршрутов для каждого шага и клиента:

```json
{
  "schema_version": "cosmo-A-result-1.0",
  "effective_scenario": { ... },
  "routes": [
    {
      "t_s": 0,
      "client_id": "C65",
      "path": ["C65", "S101", "S205", "G_MUR"]
    },
    {
      "t_s": 120,
      "client_id": "C65",
      "path": []
    }
  ]
}
```
> Пустой массив `path: []` означает отсутствие сквозного маршрута на данном шаге.
